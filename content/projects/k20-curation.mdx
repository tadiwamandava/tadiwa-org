## What it is

A classroom content-curation platform: curators sign in, pull items into
collections, tag and order them, and publish the result to a public-facing view. React
front end, AdonisJS API, PostgreSQL underneath, deployed and used in production.

The application was already live when I began the TypeScript migration.
New features still had to ship while I converted the existing modules.

## TypeScript migration

The starting point was a JSX codebase with no type coverage and an active feature
roadmap. The approach:

1. Enable `allowJs` with `checkJs: false` so JavaScript and TypeScript modules can coexist.
2. Convert utility modules first, keeping each change small enough to review and deploy.
3. Define `Item`, `Collection`, `Tag`, and `Curator` before converting the components
   that use them.
4. Keep strict settings enabled on converted modules.

The migration exposed API fields that could be null but were rendered
unconditionally by the UI. I added checks at those call sites.

## Rendering and query latency

Feedback often described the symptom without identifying the cause. “The list
feels slow” meant a rendering problem on one screen and a query problem on
another. I had to reproduce each report before deciding where to fix it.

I also left instrumentation too late. Without request-latency measurements,
performance conversations were harder to resolve. I would add that visibility
earlier on the next project.
